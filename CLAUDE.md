# TradeVerse

Экономическая браузерная игра: backend FastAPI + Motor/MongoDB (`backend/*.py`), frontend React 18 + Vite (`frontend/src/`).
Архитектура, карта файлов и где что искать — skill `tradeverse-map`: вызывай его в начале любой задачи по проекту, не исследуй структуру вслепую.
Все деньги идут через `backend/ledger.py`, коэффициенты экономики — через `backend/econ.py`, фоновые задачи — один цикл `backend/scheduler.py`. Никаких заглушек и хардкода там, где должна быть полноценная логика.

## Комментарии

Пиши комментарии ТОЛЬКО когда код не объясняет сам себя. Добавлять комментарий «по ходу дела», переписывая строку своими словами, — запрещено.

Можно и нужно (WHY, невидимое в коде):
- ловушки и прошлые баги: dotted-ключи в Mongo `$set`, naive-даты, гонки check-then-insert, молчаливые деградации;
- калибровку баланса: проценты окупаемости, множители, доли — числа, которых нет в коде;
- контракты через границы: каким полем фронт читает, какой slug ждёт бэкенд;
- намеренные упрощения с потолком (`# ponytail: …`);
- функциональные директивы: `# noqa`, `# type: ignore`, `// eslint-disable` — не трогать.

Нельзя (WHAT, история, дубли):
- пересказ кода: `# получаем пользователя` над `get_user()`;
- changelog-нарратив: «раньше было X, после фикса Y работает» — для этого есть git;
- docstring-пересказ сигнатуры (кроме обработчиков FastAPI: их docstring уходит в OpenAPI, держать одной строкой);
- перечисление параметров/возврата, если имена очевидны;
- блоки больше 4 строк: не влезло — это документ, место ему в skill `tradeverse-map`.

 Правя чужой код: новые комментарии не плодить, существующие WHY-пояснения не удалять, пока они верны. Комментарий, противоречащий коду, — исправить или удалить; врать хуже, чем молчать.
